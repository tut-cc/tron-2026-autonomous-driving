## プロジェクトの目的

この教材は、自動運転車そのものを作ることより、**自動運転システムがどう判断し、いつ止まり、いつ人間に操作を返すのか**を体験して理解することを目的にしています。

車載カメラの画像をAIが認識して走行路（白い路面）と障害物（人・車両）を見つけ、自動で走ります。AIが自信を持てないとき、通信が途切れたとき、前方に危険があるときには、μT-Kernel 上の安全制御が走行を止めます。利用者はスマートフォンのWeb画面から、今の状態と「なぜ止まったか」を確認しながら、手動運転と自動運転を行き来できます。

AI（認識）と RTOS（安全制御）を別々のCPUコアに分け、**最終的にモーターを動かす権限は安全側の μT-Kernel だけが持つ**構成にしています。AIやWebが止まったり遅れたりしても、安全判定を迂回できません。

## システム構成

```text
スマートフォン / PC（ブラウザ）
    │  HTTP（100 ms ごとに操作要求を送り、応答で車両状態を受け取る）
    │  Wi-Fi ── ルーター ── Ethernet
    ▼
EK-RA8P1
 ├─ CPU0：Cortex-M85（μT-Kernel 3.0 + lwIP）
 │    ├─ Webアプリ配信・操作要求の受付
 │    ├─ カメラ（OV5640）→ AI認識（YOLO-Fastest / Ethos-U55 NPU）→ 走行路認識
 │    └─ 認識結果・操作要求を CPU1 へ送信（共有メモリ IPC）
 │
 └─ CPU1：Cortex-M33（μT-Kernel 3.0）── 車両状態の正本
      ├─ 状態管理（MANUAL / AUTO / 停止 / 緊急停止）
      ├─ 距離センサ（ToF）監視
      ├─ AI・通信の鮮度監視、安全判定
      └─ モータ制御（DRV8833）── 左右独立モータ（差動二輪）
```

- **車両状態を決めるのは CPU1（M33）だけ**です。Webアプリは「MANUAL/AUTO 切替」「前進・左右旋回」「ABORT（STOP）」を**要求**するだけで、実際の状態（モード、停止理由、前方距離など）は毎回の応答（Heartbeat）としてマイコンから返ります。
- AIが送るのは「走行路の位置・確信度」「障害物の位置・確信度」といった**認識結果**で、モーターの指令値ではありません。

## 動作モードと一連の動作

```text
起動（停止・MANUAL）
 │ 操作ボタンを押す                 AUTO ボタン（開始条件がそろえば）
 ▼                                  ▼
MANUAL ── ボタンを離す → 停止       AUTO ── 走行路を見失う・AIが途絶
                                     ▼
                                    TOR（出力 0、3 秒のカウントダウン）
                                     ├─「手動操作に切り替える」→ MANUAL（停止）
                                     └─ 3 秒応答なし → 停止（引継ぎ時間切れ、ABORT で解除）
                                     │
どのモードでも：前方 100 mm 以内（ToF）→ 停止（STOPPED）
               前方 50 mm 以内（ToF）、AI が進路上の人・車両を検出、
               ESTOP、M85 の停止 → EMERGENCY（最優先で出力 0）
```

| 状態 | 内容 |
|---|---|
| **MANUAL** | ラジコン式：**左手で前進、右手で左右**。ボタンを**押している間だけ**走る（後退はない）。左に曲がると右タイヤ、右に曲がると左タイヤが前に回る。操作要求が 300 ms 途切れると停止 |
| **AUTO** | カメラAIの走行路認識に沿って自動で走る。開始時に ToF・CPU0 との通信・AI の走行路がそろっていないと拒否し、理由を表示（「距離センサー(ToF)が準備できていません」「M85とM33の通信が途切れています」「走行路を認識できていません」） |
| **停止（STOPPED）** | STOP（ABORT）操作、ToF が 100 mm 以内（通常停止）、通信途絶、TOR の引継ぎ時間切れで停止。原因が消えても**自動では再発進しない**。100 mm 以内では開始も拒否 |
| **EMERGENCY** | ToF が 50 mm 以内、AI が進路上に人・車両を検出、ESTOP、CPU0 の停止を検出したときに最優先で停止。ToF・AI・通信による停止は原因が消えると（ToF は 101 mm 以上）解除されるが、再発進には操作が必要。ESTOP（プロトコル上は残っているが、Web 画面にボタンは無い）は基板をリセットするまで解除されない |
| **TOR（運転引き継ぎ要求）** | AUTO 中に走行路を見失う・AI が途絶すると、CPU1 がモーター出力を 0 にして TOR に入る。Web 画面に警告と 3 秒のカウントダウン（CPU1 の時計基準）を表示し、「手動操作に切り替える」で MANUAL（停止）へ引き継ぐ。条件が戻っても**自動では AUTO に復帰しない**。3 秒以内に応答がなければ「引継ぎ時間切れ」で停止し、`ABORT` で解除する。TOR 中も ToF・ESTOP・AI の緊急停止は最優先 |

## ハードウェアの組み立て・接続（輸送後の復元）

![配線](docs/images/wiring.jpg) <!-- TODO: 写真を追加 -->

1. 車体を平坦な場所に置き、**車輪を浮かせる**（台に載せる）。
2. EK-RA8P1 が所定の位置に固定されていることを確認する。
3. モータードライバ（DRV8833）と左右モーターの配線を確認する。
4. 距離センサ（ToF）のケーブルを確認する。
5. カメラ（MIPI）のケーブルを確認する。カメラは上下逆向きに取り付ける設計（ファームが画像を 180° 回転して処理する）。
6. EK-RA8P1 の Ethernet ポートとルーターを LAN ケーブルでつなぐ。
7. モーター用電源（単3形電池 3 本、直列）を接続する。
8. EK-RA8P1 の USB 電源を接続する。

| 接続 | EK-RA8P1 側 | 相手側 |
|---|---|---|
| 右モーター | PMOD1-7（P006）/ PMOD1-8（P402） | DRV8833 AIN1 / AIN2 |
| 左モーター | PMOD1-9（P412）/ PMOD1-10（P413） | DRV8833 BIN1 / BIN2 |
| 距離センサ ToF（VL53L1X, I²C 0x29） | IIC1：P511 / P512 | SDA / SCL |
| カメラ（OV5640） | MIPI CSI コネクタ | — |
| モーター電源 | —（ボードからは給電しない） | DRV8833 VM ← 単3×3 直列 |
| GND | GND | DRV8833・電池の GND と共通 |
| ネットワーク | Ethernet | ルーター |
| ボード電源 | USB（J-Link OB 側） | USB 電源 / PC |

左右の割り当ては `control/include/motor_build_profile.h` の `MOTOR_SWAP_SIDES`（現在 1 = AIN が右）。配線を入れ替えた場合は 0 にして両コアをクリーンビルドする。

## 起動方法（Getting Started）

ファームは書き込み済みです（開発者向けのビルド・書き込みは最後の節）。

### 1. 電源投入
1. ルーターの電源を入れ、EK-RA8P1 と LAN ケーブルでつながっていることを確認する。
2. モーター電源を接続する。
3. EK-RA8P1 の USB 電源を接続する。起動後 約 10 秒でネットワークにつながる（**LAN ケーブルは電源投入前に挿しておく**）。
4. 起動直後は MANUAL・停止状態。操作しない限り動かない。

### 2. スマートフォンをネットワークに接続
ルーターの Wi-Fi に接続する。

- パスワード：同梱の紙を参照 <!-- TODO -->

### 3. Web UI を開く
ブラウザで **http://192.168.2.200/** を開く。画面上部に状態と前方距離（mm）が表示されれば接続成功。
（固定 IP。ゲートウェイ 192.168.2.1、ネットマスク 255.255.255.0）

### 4. MANUAL で動作確認
左手で画面左下の「▲」を押している間、車両が前進すること、離すと止まることを確認する。右手で画面右の「◀」「▶」を押すと旋回し、▲と同時に押すと曲がりながら進む。PC ではキーボードの `↑/W`・`←/A`・`→/D` でも操作できる。

### 5. AUTO
車両を白い路面（白い紙・白いコース）に置き、`MANUAL MODE` ボタンを押して AUTO に切り替えると自動走行を始める。止めるときは `ABORT`（停止ボタンはこれ1つ。`RESET` で再開できる）。

## デモシナリオ（審査で試してほしいこと）

1. 電源を投入し、Web UI を開く。
2. MANUAL で前進・左右旋回を確認する（ボタンを離すと止まる）。
3. 白い路面の上で AUTO に切り替え、自動走行を確認する。
4. 車両の前に手や箱を置き、**距離センサで緊急停止**することを確認する（Web に停止理由が出る）。障害物を取り除いても自動では再発進しない。
5. 路面の外（白くない場所）で AUTO を押し、**「走行路を認識できていません」で開始を拒否**されることを確認する。
6. 人や車の写真（印刷物）をカメラの前にかざし、AI の検出で停止することを確認する（人を車両の前に立たせない）。
7. `ABORT` で即時停止し、`RESET` を押すまで再発進しないことを確認する。
8. Web を閉じる・Wi-Fi を切ると、MANUAL は 300 ms で停止することを確認する。

9. AUTO 走行中に車両を白い路面の外へ持ち上げる（またはカメラを手で覆う）と、**TOR 表示と 3 秒のカウントダウン**が出て車両は止まることを確認する。
   - 「手動操作に切り替える」を押すと MANUAL に引き継がれる。
   - 押さずに 3 秒待つと「引継ぎ時間切れ」で停止する。`ABORT` で解除して MANUAL に戻る。

## TRON / μT-Kernel 3.0 の使い方

2 つのコアの両方で μT-Kernel 3.0 を動かしています。

**CPU1（Cortex-M33）：安全制御**
| 優先度 | タスク | 役割 |
|---:|---|---|
| 1（最高） | emergency | 緊急停止の処理 |
| 2 | motor | モーター出力（DRV8833、PWM 上限・加速制限） |
| 3 | distance | 距離センサ（ToF）の監視 |
| 4 | decision | 状態遷移（MANUAL / AUTO / 停止 / 緊急停止）と安全判定 |
| 5 | web | Web からの操作要求の受付 |
| 6 | vision | AI 認識結果の受付と鮮度チェック |
| 7 | status | 状態の通知（CPU0 / Web へ） |

- **安全系（緊急停止・モーター・距離監視）を、AI や Web の処理より高い優先度で動かす**ことで、認識や通信が混んでも停止処理が遅れないようにしています。
- タスク間は μT-Kernel のメッセージバッファ・イベントフラグ・優先度継承ミューテックスでつなぎ、走行中に動的メモリ確保をしません。

**CPU0（Cortex-M85）：認識と通信**
| 優先度 | タスク | 役割 |
|---:|---|---|
| 8 | IPC gateway | CPU1 への認識結果・操作要求の送信（STOP/ESTOP は専用スロットで優先） |
| 10 | lwIP | Web サーバー（HTTP） |
| 12 | camera | カメラ取得・AI 推論・走行路認識 |
| 20 | video | PC への USB 画像配信（最低優先度） |

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| Web が開けない | スマホがルーターの Wi-Fi（192.168.2.x）にいるか。LAN ケーブルを挿してから EK-RA8P1 の電源を入れ直す |
| AUTO が拒否される | 画面の理由を見る。「走行路…」なら白い路面が画面下半分に大きく映るように置き、照明を明るくする。「距離センサー…」なら前方 100 mm 以内に物がないか、ToF の配線 |
| MANUAL がすぐ止まる | Wi-Fi の遅延で操作要求が 300 ms 以上途切れている。ルーターに近づく |
| 停止後に動かない | 仕様（安全のため自動では再発進しない）。もう一度ボタン操作をする。停止理由が「ボタンによる緊急停止」なら基板をリセットする |
| 映像が止まる・遅い | INFO の GET 時間・フレーム率を見る。映像は制御より低優先のベストエフォート（目標 10 fps、保証なし）で、映像が止まっても制御の安全判定には影響しない |
